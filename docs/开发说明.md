# 开发说明

桌边记是 WPF（.NET 10）程序，图标是 Fluent UI System Icons（只留用到的图标的小字体），托盘用 H.NotifyIcon.Wpf，Markdown 用 Markdig，网页粘贴用 AngleSharp；版本号和依赖版本以 `src/Zhuobianji/Zhuobianji.csproj` 为准。

版本号只写在 csproj 的 `<Version>`：设置的“关于”页、托盘悬停文字、exe 属性都从程序集读（`AppInfo`）。README 顶部和使用说明开头写着版本号，发版时跟着改，`build-app.ps1` 会核对，漏改就不构建。开源地址、使用说明和发布页的地址只写在 `AppInfo`。

命名：面向用户一律叫「桌边记」，本地程序是 `桌边记.exe`；代码、工程和命名空间用 `Zhuobianji`。GitHub 发布附件名不支持中文，上传为 `Zhuobianji.exe`。开机启动项的注册表值名沿用早期的 `WeNote`，不要改，否则已开启自启的用户升级后开关会失效。

## 主要流程

**分层**：便签的状态在 Core 的 `NoteBook`（全部便签、收纳关系、改状态入口、保存、设置）和 `NoteEntry`（一张便签的数据、是否待保存、保存错误），不引用 WPF。NoteController 按状态建窗口、显示隐藏，管托盘、设置、快捷键和桌面模式；NoteWindow 只管界面，开着窗口时实现 `INoteView`：保存前交出编辑器里的正文和窗口位置（Capture），存完收到结果（Saved）。状态变了 NoteBook 发 `Changed`，窗口和主便签的标签据此刷新。控制器的操作里，用户在某个窗口上做的（关闭、贴桌面、收纳、设为主便签）收 NoteWindow，可能针对没开窗口的便签的（显示、展开、取出、删除）收 NoteEntry。

**启动**：Program 选定 Data（EXE 旁边，或 `--data-dir`），建立 NoteStore 和 NoteController。Start 由 NoteBook 读入便签和偏好，先恢复收纳关系，再只给要显示的根便签建窗口、恢复桌面模式；全部隐藏时找回最近一张根便签，普通浮窗前置。隐藏、收纳的便签启动时不建窗口（每张约省 25 ms），第一次显示时由 `WindowFor` 建，之后一直留着，收起只是隐藏（再点开 2 ms，重建要 130 ms 左右）；记着贴桌面的根便签建窗口时挂回桌面。正文读不了的便签在建窗口时提示，并从内存里拿掉（原文件保留）。主便签读不了（文件读不了，或建窗口时正文读不了）时，收着的便签放回桌面并显示出来。便签文件里收纳顺序写成 null（手改或损坏）时当作没记顺序。0.8.x 第一次启动迁移深浅色时设置没存上，便签里的旧 Dark 先留着，下次启动再迁移。

**保存**：正文变化 → NoteWindow.MarkDirty → 400ms 防抖 → SaveNow → NoteBook.Save → 向窗口取正文和位置 → NoteStore.Save。拖动、缩放期间暂停写盘，松手后续写。NoteStore 先写临时文件再替换，保留上一版 `.bak`；同一个 Data 只允许一个程序实例写入。

**状态字段**（隐藏、收纳、排序、置顶、桌面模式等）只通过 NoteBook 的两个入口修改（窗口上的同名方法转给它）：
- `Update(change)`：改字段并排队保存，用于失败也不影响界面的操作（置顶、显示）。
- `TryCommit(change)`：改字段并立即保存，失败恢复原状态，用于必须落盘才能继续的操作（关闭隐藏、收纳、取出、排序）。

**关闭与删除**：×、Ctrl+W 都是保存并隐藏，保存失败时窗口留在原处并提示重试。主便签关闭时先收起展开的子便签。删除先经 `Dialogs.Confirm`；删除主便签时先逐张把收纳的便签释放到桌面，某张存不上就停下、主便签不删，提示里说明已取出几张。托盘退出和关机、注销（会话结束，`EndSession`）都先 FlushAll，再把窗口彻底关掉（ClosePermanently）；任何一张没存上就不退出。会话结束不先关窗口的话，系统随后关窗口会走 × 的路，把每张便签存成隐藏。

**保存失败给谁看**：便签窗口开着时，由窗口底部的「保存失败 · 点击重试」显示；针对没开窗口（没建、隐藏、收起）的便签的操作存不上时（标签菜单取出、删除主便签时释放、托盘批量切换桌面模式），由控制器弹提示说明是哪张、为什么。

**桌面模式**：DesktopHost 把窗口挂到桌面层，管理父窗口、样式和坐标，挂载失败恢复原状态。这些原生恢复代码有实际用途，不是多余的防御。便签窗口四周留 12px 透明边距画阴影（`NoteWindow.ShadowMargin`，和 NoteWindow.xaml 里 Frame 的 Margin、WindowChrome 的标题高度与缩放边一致），主便签左侧再留一块透明标签区（基准 92px；标签随主便签卡片大小按 0.1 一档放大到最多 1.6 倍，标签区宽度只放大一半，拖动缩放松手后才改宽度，见 NoteWindow.Collection 的 `RailScale`）；Snapshot 保存的位置和尺寸只算正文卡片，不含这两块。

## 外观怎么改

- 颜色和间距只在 NoteTheme 里改。`ApplyTo` 把配色写成窗口资源键（Surface Header Text Muted Edge Accent Subtle Selected Danger Error），NoteStyles.xaml 和 NoteWindow.xaml 只用 `DynamicResource` 引用这些键，换主题时界面自动跟着变。Subtle、Selected 是正文色加透明度，用作按钮的悬停底和选中底。
- 深浅色是整个程序的模式（`NotePreferences.ThemeMode`：浅色、深色、跟随系统），配色、字体、字号、透明度才是每张便签自己的，便签里不存深浅色。设置里的“应用到全部便签”把一张的字体、字号、透明度推给其他每张（`NoteController.ApplyAppearanceToAll`），配色不动；没开窗口的便签不为它建窗口，由 `FormattedDocuments.Restyle` 直接改存着的富文本（局部字号按比例、写着旧正文字体的改成跟随），和开着窗口时换外观是同一段代码。透明度是整个窗口的 Opacity（字也跟着变淡）。设置里的滑块是 0–100，按直线换成窗口的 70%–100%（`NoteTheme.OpacityOf` / `OpacityLevel`，下限 `MinOpacity`）：0 最透明但字看得清，100 不透明。存储里是窗口实际的不透明度，只在拖滑块时换算，换配色、字号不动它；旧数据里低于 70% 的按 70% 显示。现在是深是浅只记在 `NoteTheme.DarkMode`，由 NoteController 按设置写入；`NoteTheme.For(appearance)` 按它取色，便签、标签、弹窗、托盘菜单都不用单独处理深浅色。换模式时每张便签重新应用一遍外观（不算改正文，不更新修改时间），编辑器记着上次显示用的主题，把正文里旧主题的颜色换掉。跟随系统读 `HKCU\…\Themes\Personalize` 的 `AppsUseLightTheme`，系统切换时由 `SystemEvents.UserPreferenceChanged` 通知。0.8.x 每张便签各存一份 `Dark`、设置里没有 ThemeMode：第一次启动按主便签（没有就按默认外观）定下模式并马上存进设置；旧的 `Dark` 读进 `NoteAppearance.LegacyDark`，用完就清掉，不再写出。
- 字体：正文字体名都经过 `NoteTheme.Font(name)` 变成 FontFamily。「思源黑体」是随程序打包的 Source Han Sans CN 简体子集（`Assets/Fonts`，常规和粗体，SIL OFL 1.1，许可在 THIRD-PARTY-NOTICES），存储里只写名字「思源黑体」。界面文字（顶栏、底栏、菜单、弹窗）固定用微软雅黑 UI。
- 图标：`NoteIcon` 按文字画 Fluent UI System Icons 的字形（MIT），样式 `Icon` 定为 16px，颜色跟着文字。字体在 `Assets/Icons`，是从 WPF UI 4.3.0 自带的完整字体（各 2.5 MB 左右）里只留用到的图标裁出来的，两个加起来不到 10 KB。加图标：查到它的码位（WPF UI 4.3.0 的 `SymbolRegular`，或 Fluent 仓库字体旁的 json），加进 `NoteIconSymbol`（实心的再加进 `NoteIcon.FilledGlyphs`），然后运行 `scripts\subset-icons.ps1`（要 Python 和 fontTools，只在加图标时用）。close 组会检查每个图标都有字形。
- 立体感只有一种做法：便签上能点的按钮都放在凸起的键托 `KeyTray` 上（顶栏、底栏左右各一个，排版栏一个），托里的按钮平时是平的，悬停浮起，按下和开启时凹进去；凹只表示按下或开启。图标按钮 `IconButton` / `IconToggle`（28×28，平时淡色、悬停变实），带文字的 `LabelButton` / `LabelToggle`，文字按钮 `ToolButton`。弹窗里的按键单独凸起（`KeyButton`），确认用墨色实底的 `PrimaryButton`，危险操作用红底的 `DangerButton`。左侧标签用同一种凸起，尺寸由代码写成标签区资源；标签列最下面的「新建」是单独的小键（`NewTab`，四角圆角、顶栏色实底，不压到卡片下面）。底栏格式键和格式菜单用图标区分三种格式（`NoteWindow.FormatIcon`），切换格式或 Markdown 源码 / 预览时正文淡入。尺寸、圆角、字号的约定写在 NoteStyles.xaml 开头。
- 动画时长用 `NoteTheme.Fast`（120ms，悬停、淡入）和 `NoteTheme.Standard`（180ms，展开、滑出），缓动用 `NoteTheme.Ease`；系统关闭窗口内动画时时长为 0。只动透明度和位移；资源里的画刷是冻结的，悬停变色靠叠一层底色改透明度。颜色面板和链接卡片用 Popup 自带的淡入，菜单跟随系统菜单动画设置。
- 便签窗口出现时淡入（`NoteWindow.Reveal`）。透明窗口隐藏后，系统还留着它隐藏前的最后一帧，再显示时会先贴出这帧不透明的旧画面，程序随后才从透明淡入，看起来闪一下（展开子便签时约四次里一次）。所以显示过的窗口先让系统暂不画它（DWM cloak），画出淡入的头两帧再露出来；第一次显示的窗口没有旧画面，不用等。贴桌面的窗口是桌面的子窗口，不能 cloak，照旧。
- 文字清晰度：便签是透明窗口（AllowsTransparency），默认只能灰度抗锯齿。NoteCard 上设了 `RenderOptions.ClearTypeHint`，顶栏、底栏和排版栏用 `TextFormattingMode="Display"`，这些小字是 ClearType。正文是灰度：文字上层只要有裁剪就只能灰度，滚动区一定会裁剪。去掉滚动区裁剪能让正文变成 ClearType，但代码块底色、表格线、引用竖线是整块画的，滚动时会画到卡片外的阴影边距里，所以没有采用；要做得先把阴影挪出便签窗口。
- 开关型按钮（置顶、源码 / 预览、标签开关、收纳标签）是 ToggleButton，开启时的底色由样式按 `IsChecked` 决定，代码只设置 `IsChecked`。
- 弹窗（提示、确认、链接、设置）共用 `NoteDialog` 外壳：配色跟着所属便签，顶栏、键托和按键与便签相同，出现时淡入并略微放大；输入框、开关、滑块、勾选框和配色色块的样式也在 NoteStyles.xaml。设置窗口在便签旁边打开。
- 弹窗里的改动都是点主按钮才算数（链接窗口的“确定”、设置窗口的“完成”）。设置窗口为了马上看到效果，外观、深浅色、自启、格式提示一改就用上（也会存），没点“完成”就关窗（取消、×、Esc、换一张便签开设置、退出程序）时由 `SettingsWindow.Revert` 退回打开时的值；只退这个窗口自己改的，别处同时改过的项（比如托盘开关自启）不动。“设为默认外观”“应用到全部便签”“保存快捷键”本身就是保存，点了就算数。
- 托盘是 H.NotifyIcon.Wpf，右键菜单是 WPF 菜单，样式和便签菜单相同，配色用默认外观加当前深浅色。
- 富文本存储不写主题值（`FormattedDocuments.SaveRich / LoadRich`）：根上的字体、字号、行高、正文色，以及等于主题色的文字色和链接色都会去掉，读取时按当前主题补上，所以调整主题色后旧便签也会跟随。0.8.x 写进存储的旧主题色列在 `NoteTheme.LegacyText / LegacyLink`，改主题色时这两组旧值保持不动。
- Markdown 和网页粘贴生成的代码底色、引用文字色、表格和分隔线边框存储时保留（代码块靠底色识别），读取、粘贴和换主题时换成当前主题的颜色（`FormattedDocuments.ApplyReadingLayout`，判断见 `NoteTheme.IsThemeCode` 等）。网页和其他程序带来的近黑、近白文字色和底色粘贴时去掉，改为跟随主题（`NoteTheme.IsPageNeutral`），有颜色的保留。
- 代码块、行内代码只按显式设置的 Consolas / Courier 识别（`DocumentText.IsCode`），便签字体选 Consolas 不会把正文当代码。
- Markdown 源码里的语法符号变淡（`SourceSyntax`）：源码是普通 TextBox，不能给几个字单独上色，所以在它的文字层上加一层装饰（Adorner，在光标下面），给看得见的几行里的语法字符盖一层 40% 的便签底色（`NoteTheme.SyntaxVeil`）。正文卡片的底色是纯色、透明度是整个窗口的，盖一层和把字的颜色往底色调一样。哪些是语法由 `MarkdownSyntax` 用和预览同样的 Markdig 扩展（带精确位置）解析，变淡的正好是预览里会消失的符号。改字、滚动、选中后等这一轮排版完（LayoutUpdated）再画，和文字同一帧；选中的字不盖。第一次解析放在窗口出来之后，超过 2 万字的便签放到空闲时解析。

## 构建、安装、发布

需要 Windows 和 [.NET 10 SDK](https://dotnet.microsoft.com/zh-cn/download/dotnet/10.0)（`dotnet` 在 PATH 里）。在项目根目录：

    powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-app.ps1

输出 `.local/build/current/桌边记.exe`，旁边的 `docs` 里是使用说明和两份第三方许可（许可同时嵌在程序里）。这是自带运行库的 x64 单文件程序，使用者不用装 SDK。构建失败时保留原来的输出。

自己用：把 `桌边记.exe` 复制到想放的文件夹运行，便签存在它旁边的 `Data` 里。升级和 README 里给用户的步骤一样：先从托盘退出，备份 `Data`，再用新的 exe 替换旧的。

发布：先改 csproj 的 `<Version>`，README 顶部和使用说明开头的版本号一起改；构建后把 `桌边记.exe` 以 `Zhuobianji.exe` 的名字上传到 GitHub Release，标签写 `v版本号`。README 的下载链接和“关于”页的“下载新版”指向最新的 Release。仓库的社交预览图（`social-preview.png`，1280×640）由 preview 组生成，在 GitHub 仓库设置里上传。README 用的截图（`docs/images` 里的 demo.png、formats.png、collection.png、links.png、markdown-source-dark.png、settings-dark.png）是 preview 组的输出原样复制过去的，界面改了就重跑 preview 组再复制；下载按钮 download.svg 是手画的，文字固定不写版本号。

脚本里有中文，必须保存为带 BOM 的 UTF-8，否则 Windows PowerShell 5.1 会按 GBK 读错。C# 和 XAML 文件不加 BOM。

## 检查

功能检查是一个自带的控制台程序（`tests/Zhuobianji.Checks`），不依赖测试框架。检查分两层：

- 不开窗口的三组（`quick`）：storage 测存储，state 直接测 NoteBook（只用 Core，不起界面程序；窗口用一个假的 INoteView 代替），documents 用单独的编辑器测粘贴、转换、链接名称和排版（起 WPF，不显示窗口）。不弹窗、不抢前台，几秒跑完。
- 开窗口的组：在真实桌面上开便签窗口操作，只测界面那一半——窗口跟着状态变、按钮和菜单链路、提示框、动画、桌面挂载、截图、换个进程重开。

状态规则和文档转换改了先看不开窗口的组；窗口组里不重复断言它们已经测过的东西。统一入口：

    .\scripts\test-app.ps1                      # 列出功能组
    .\scripts\test-app.ps1 -Group quick         # 不开窗口的三组，几秒
    .\scripts\test-app.ps1 -Group storage,close # 运行指定组

注意：开窗口的组会弹窗、抢前台。同一台机器上同时操作其他窗口时，startup 组的「启动到前台」等检查可能偶发失败，先单独重跑该组再下结论。desktop、collection、rail 需要真实登录桌面（有 Progman）。

按改动选相关的组；改动中间随时可以跑 quick，改动范围大或要发布时再跑全部。

## 测量

改动启动、内存或发布设置的前后各跑一次测量，对比数字（同样会弹窗、抢前台，约 3 分钟）：

    .\scripts\measure-app.ps1 -Label '改了什么'   # 默认测 .local/build/current/桌边记.exe，-Exe 换别的程序

脚本生成两套假便签，形状照常见用法（1 张主便签显示，七成收纳，其余隐藏；大多富文本，少量 Markdown 和纯文本），10 张和 50 张。每套「首次启动」3 次（.NET 解压本机库的目录是空的，相当于升级后第一次打开），「再次启动」5 次。每次记录出现第一个窗口的时间，以及 5 秒后的 CPU 时间、工作集、专用内存、句柄、GDI / USER 对象；另外记录程序大小和解压出的本机库大小。用独立 Data，关掉快捷键（避免和正在用的桌边记冲突），不碰正式便签；退出时发会话结束消息，让程序走正常退出。

中位数追加到 `.local/measure/history.csv`（带提交号和 `-Label`），每次的明细在同次目录的 `result.json`。同一台机器上两遍之间差 3% 左右，差得比这大才算有变化。

## 取舍与以后再说

- 轻量是初心：可以引入库，但只引入小而专一的；不引入大型界面框架和浏览器内核。图标只用 Fluent UI System Icons（按需裁出的小字体，不引入整个图标库），动画只用 WPF 自带的 Storyboard。
- 界面上已经定下的取舍：
  - 顶栏按钮一直显示（平时淡色、悬停变实），不做悬停才出现：按钮会跳出来，也不好找。
  - 排版用底部固定的排版栏，不做选中文字浮出的工具条：会和链接卡片抢位置。
  - 普通便签的顶栏标题留空，只当拖动区；主便签顶栏左边是「主便签」键，兼作左侧标签的开关。
  - 按钮的悬停底和选中底用正文色加透明度，不用 Accent：固定的蓝色放在奶油、淡黄、浅绿便签上不协调。
- 运行和发布的取舍（桌边记常驻托盘，按「内存 > 体积 > 启动」排轻重；数字是 10 张便签、1920×1080 屏幕上测的）：
  - 软件渲染（`Program.UseSoftwareRendering`，检查程序也调用它）：不建显卡设备。启动后专用内存 93 → 63 MB，操作一阵之后 140 → 94 MB，便签拉大到 880×980 时 188 → 89 MB；启动快约 11%。截图（含 ClearType 小字）和展开动画都和硬件渲染一样。代价是滚动、拖动缩放时 CPU 多 15–20%；880×980 的大便签（高分屏上一张普通便签的像素数）快速滚动时 CPU 约 2.3 倍，每秒画面从 26 帧降到 21 帧。空闲、打字、展开收起没有差别。
  - 测过不用的发布设置：单文件压缩（程序小一半，但启动慢 180 ms、内存多 70–110 MB）；合成预编译（快 13%，程序大 20 MB、内存多 5 MB）；不合成预编译 + System.Text.Json 源生成（快 30–50 ms，大 3 MB；而且源生成读 init 属性时，文件里缺的字段会变成空值和 0，不取代码里的默认值，早期的便签读不了）；关后台 GC（没变化）。
- 以后再说：
  - 待办清单（☐）等新功能；选中文字浮出工具条、顶栏悬停才出现（想换时再做）。
  - 正文 ClearType：要先把阴影挪到单独的窗口，见「外观怎么改」里的文字清晰度。
  - 彩色 emoji：WPF 的文字只能画单色，要换编辑控件，风险大。
